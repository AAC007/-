# PROJECT_CONTEXT.md

## Продуктовая цель

"Заказ заготовок для ЦМО" - настольное приложение для автоматического формирования закупочной потребности по материалам и заготовкам. Оно должно отвечать на практический вопрос снабжения и производства: какую деталь нужно изготовить, какая заготовка для нее нужна, в каком количестве и к какому сроку ее нужно купить, чтобы закрыть текущую производственную потребность с учетом уже имеющихся остатков и НЗП.

Проект рассчитан на развитие: справочник деталей и заготовок должен накапливаться, уточняться вручную, переживать повторные импорты и масштабироваться до десятков тысяч деталей.

## Основной поток данных

1. Пользователь импортирует НСИ/номенклатуру заготовок из 1С.
2. Пользователь импортирует или редактирует библиотеку соответствий: деталь IPS -> заготовка/УТ-код/норма расхода.
3. Пользователь импортирует производственную потребность из ПП.
4. Приложение синхронизирует остатки склада из 1С напрямую; Excel-импорт остатков оставлен как резервный канал.
5. Приложение рассчитывает потребность в заготовках:
   - находит деталь по IPS;
   - применяет активную связь с заготовкой;
   - умножает количество деталей на норму расхода;
   - учитывает процент потерь;
   - вычитает НЗП по IPS через 11-значный цифровой ключ 1С: например, IPS `1802132` сопоставляется с кодом 1С `00001802132`; в пользовательской потребности НЗП отображается как "В производстве";
   - вычитает складской остаток по УТ-кодам/алиасам заготовки;
   - формирует количество к закупке;
   - показывает срок потребности по детали/заготовке;
   - считает дату потребности заготовки как `дата потребности детали - срок заготовки из библиотеки`; базовое значение срока - 30 дней.
6. Пользователь экспортирует Excel-отчет, включая лист "Заявка" для снабжения. Заявка должна содержать список деталей и заготовок со сроками потребности.

## Текущий стек

- .NET 8 / C# / WPF.
- MVVM через `CommunityToolkit.Mvvm`.
- SQLite + EF Core.
- Excel: EPPlus, DocumentFormat.OpenXml fallback-reader.
- Логирование: Serilog.
- Тесты: xUnit + FluentAssertions.

- Импорт номенклатуры заготовок из 1С.
- Выполнена разведка установленного `IPS Viewer` для будущей привязки деталей к данным IPS и PDF-чертежам. Закреплены локальный ClickOnce-кэш, основные таблицы `IMS_*`, атрибуты и способ чтения файлов из `IMS_STORAGE.F_FILEBODY`; рабочее подключение к базе IPS пока не найдено. Подробности: `docs/IPS_VIEWER_INTEGRATION_NOTES.md`.
- Подготовлен отдельный проект `onec_integration` для безопасной интеграции с 1С:УТ 10.3: обследование метаданных, COM-клиент, быстрый read-only запрос остатков, синхронизация секций остатков для WPF, шаблоны 1С-модулей, dry-run создания документов, журналирование и предохранители записи.
- Для оперативных запросов остатков закреплена команда `onec_integration\lookup_1c_stock.cmd`; она читает `ТоварыНаСкладах` и сверяет результат с `ПартииТоваровНаСкладах` и `ТоварыОрганизаций`.
- Импорт производственной библиотеки соответствий деталей и заготовок, включая беззаголовочный формат `Данные из МСК.xlsx`. Поддерживаются встреченные порядки колонок: старый 12-колоночный с отдельным размером, нормой, единицей, УТ-кодом и наименованием заготовки; фактический 11-колоночный формат `IPS / обозначение / наименование детали / вид / полное наименование заготовки / материал / УТ-код / ГОСТ материала / ГОСТ сортамента / единица / норма`; компактный 10-колоночный формат `IPS / обозначение / наименование детали / полное наименование заготовки / УТ-код / материал / ГОСТ материала / ГОСТ сортамента / единица / норма`. Если IPS был ранее удален из библиотеки через архивную метку или старый текст `Удалено из библиотеки`, явный импорт МСК/библиотеки очищает след удаления и возвращает строку в рабочий список; при открытии библиотеки также восстанавливаются архивные детали, у которых после импорта уже есть активная связь с заготовкой. Если УТ-код или каноническая заготовка были архивированы в НСИ, импорт МСК возвращает их в активные позиции, чтобы заготовка снова участвовала в списке, поиске и подсказках.
- Ручное создание, редактирование и удаление/архивирование связей детали с заготовкой; в библиотеке можно добавить строку кнопкой `+`, выбрать заготовку через подсказку по формату `наименование | код`, сохранить выбор по введенному тексту, задать срок заготовки в днях, очистить редактор и удалить одну или несколько выделенных строк. Библиотека показывает также детали без активной заготовки, имеет фильтр "Связь" (`все`, `без заготовки`, `с заготовкой`) и выводит инфостроку с количеством показанных деталей и количеством деталей без заготовки по текущим фильтрам. Карточку детали без заготовки можно редактировать и сохранять без выбора заготовки; при удалении такая карточка архивируется, отвязывается от строк потребности и не создается повторно автоматически, даже если у детали остались старые неактивные карты заготовок. При ячеечном выделении редактор библиотеки заполняется по выбранной ячейке/строке, удаление выделенного собирает строки из выделенных ячеек, а правый клик выбирает строку под курсором для команд контекстного меню. При сохранении новой основной заготовки для IPS старые активные связи этого IPS архивируются, чтобы в расчете не оставались разные материалы для одной детали.
- Фильтры и поиск в библиотеке и НСИ; в НСИ можно вручную добавить заготовку кнопкой `+`, очистить редактор, редактировать и удалить строку через контекстное меню; поле "Марка материала" в редакторе НСИ имеет выпадающие подсказки по имеющимся материалам; в фильтре единиц библиотеки используются только расходные единицы `шт` и `пог. м`; среди видов заготовок есть "Поковка".
- В таблице "Библиотеки" используется ячеечное выделение `Cell`; клик по ячейке заполняет редактор, но визуально не выделяет всю строку. `DataGrid.SelectedItem` не привязан к ViewModel, чтобы WPF не пытался выбирать всю строку в режиме `Cell`; команды контекстного меню библиотеки устойчивы к служебным WPF-параметрам, которые появляются при наведении, всплывающих списках и перерисовке таблицы.
- В НСИ отображается инфострока с количеством показанных строк.
- На главной панели счетчики показывают актуальные рабочие данные, а не накопленную историю: `Деталей` считается по активным строкам библиотеки без архивных карточек, `Заготовок` - по активным строкам НСИ, `К закупке` - по последнему расчету. Карточка `Позиций 1С` убрана. Карточка `Дубли НСИ` открывает НСИ с включенным фильтром `Только дубли`; тот же фильтр доступен в верхней панели НСИ.
- Просмотр применяемости заготовки через панель НСИ; при ячеечном выделении клик по строке/ячейке обновляет применяемость. Применяемость показывает только детали с активной связью на выбранную каноническую заготовку, без похожих деталей по названию, размеру или материалу.
- В НСИ можно удалить или перенести в архив несколько выделенных строк; остаток на ЦМО отображается как `0`, если по позиции нет количества в последнем снимке остатков.
- Импорт потребности из ПП с обновлением повторно импортированного файла без дублей; повторно импортированная партия поднимается в последние, чтобы вкладка "Потребность" показывала именно загруженный файл. Новые IPS из потребности автоматически создаются как детали без заготовки, в том числе при обновлении существующей партии; библиотека дополнительно сверяет строки потребности и создает отсутствующие карточки деталей по IPS. В библиотеку из потребности добавляются только строки деталей: операции, сборки, узлы, комплекты и монтажные строки не создают карточки деталей; если наименование начинается с обозначения, оно разделяется на `Обозначение` и `Наименование`.
- Вкладка "Подбор заготовок" расположена после НСИ, подбирает позиции НСИ по виду, материалу и размерам детали, оставляет только заготовки, которые больше или равны детали по сопоставимым размерам, и сортирует результат от меньшего припуска к большему. В этой же вкладке можно выбрать или набрать IPS детали без активной заготовки из того же набора, который отображается в библиотеке; подсказки деталей раскрываются при вводе первых символов, выбранная деталь фиксируется в поле, поиск по материалу учитывает материал, каноническое наименование и алиасы НСИ. После выбора детали и заготовки можно указать норму расхода в `шт` или `пог. м` и добавить выбранную заготовку в библиотеку.
- Вкладка "МСК" читает Excel-файлы из `X:\19_МЕХ УЧАСТОК\База МСК\СПИСОК МСК`, обновляет локальный реестр `MskRecords`, сводит его с библиотекой по IPS, позволяет искать деталь по IPS/обозначению/наименованию/имени файла и открывает исходный Excel-файл МСК. Детальная панель МСК расположена справа и занимает половину вкладки; информация обновляется при поиске, выборе или наведении на строку и сразу показывает подробные поля детали и заготовки без верхней сводной табличной строки. Основная таблица МСК не показывает колонку `Файл`, но путь остается доступен в детальной карточке и команде открытия Excel МСК. При наведении и при клике по строке МСК WPF-клиент может через read-only `IPS Bridge 3.3.1` найти PDF-чертеж по IPS, сохранить его в `%LOCALAPPDATA%\BlankDemandPlanner\IpsDrawings` и открыть через системный PDF-просмотрщик; клик выполняет принудительную повторную попытку, даже если автопоиск при наведении уже пробовал этот IPS.
- Во вкладке "Потребность" можно вручную добавить строку потребности кнопкой `+`, удалить выделенные строки с возможностью отмены, сохранить ручные строки, ограничить показ по дням, видеть количество уникальных IPS, суммарное количество деталей, колонку "В производстве" по остаткам 1С и боковую панель детализации по выбранной строке IPS; панель можно скрыть и отобразить. В заголовке детализации по IPS показывается общее количество деталей в потребности и дефицит как потребность минус количество в производстве. Колонка "В производстве" показывает фактический остаток НЗП перед строкой с учетом списания строк выше.
- Прямая read-only синхронизация остатков 1С: при запуске ПО и по кнопке "Обновить данные 1С" создается обычный `StockSnapshot`; ЦМО/НЗП берется суммой по `44 секция НЗП (незавершенное производство)` и `Детали МУ в обработке на стороне`; складской остаток берется суммой по `1 секция (ПЗМЦ) только для производственных целей`, `Покраска ТМЦ`, `ТМЦ по проекту ФРП`, `ТМЦ для проверки ОТК`, `ТМЦ для временного хранения ЦСТС`, `ТМЦ для временного хранения ЦМО`. Верхняя кнопка Excel-импорта остатков убрана; Excel-импорт остается техническим резервным каналом.
- Расчет материалов с учетом склада и НЗП; заявка показывает только дефицит к закупке после вычета складского остатка, строки с нулевым количеством к заказу в окне расчета не отображаются. Заготовки вычитаются только по закрепленной группе "Склад", НЗП деталей - только по закрепленной группе "НЗП/ЦМО". Если для IPS нет активной заготовки, в колонке "Номенклатура" отображается "Новая номенклатура".
- Отображение деталей и заготовок в заявке со сроками потребности.
- Базовое правило планирования закупки: срок заготовки в библиотеке по умолчанию 30 дней, дата потребности заготовки в расчете равна дате потребности детали минус этот срок.
- Разовое назначение заготовки для строк расчета без подобранной связи или для замены в конкретном заказе: пользователь выбирает строку расчета, ищет заготовку в НСИ, задает норму расхода и добавляет заготовку только в текущий расчет; библиотека и НСИ не изменяются, при новом полном расчете разовое назначение сбрасывается.
- Расчет игнорирует дублирующие активные связи одной детали с той же заготовкой и единицей измерения.
- Экспорт расчета для Bitrix 24 создает файл `Заявка на закуп заготовок ЦМО от <дата> <номер>.xlsx` с листами "Заявка" и "По группе"; лист "Заявка" выгружает только непокрытую складом закупочную потребность без колонки "В производстве", а лист "По группе" суммирует одинаковые УТ-коды/IPS по заготовке и единице измерения.
- Экспорт библиотеки в Excel создает файл `Библиотека.xlsx` в выбранной пользователем папке; если файл открыт и занят Excel, создается резервный файл `Библиотека_yyyyMMdd_HHmmss.xlsx`. Повторный импорт отредактированного общего файла `Библиотека.xlsx` обновляет карточку детали, норму расхода и срок заготовки.
- История обновлений читает `VERSION.md`; новые заголовки версий могут содержать дату и время после версии, во вкладке "История" они отображаются отдельной колонкой "Дата обновления".
- Вкладка "История" показывает версии обновлений и краткое описание работ из `VERSION.md`.
- Вкладка "Настройки" позволяет менять шрифт, размер шрифта, положение верхних кнопок, иконку окна и путь к пользовательскому изображению.
- На главной странице карточки показателей открывают соответствующие рабочие вкладки.
- Таблицы копируют данные без заголовков колонок; в правом верхнем углу доступна отмена последних пользовательских действий до 10 шагов.
- Регрессионные тесты для расчета, импорта реальных файлов и ViewModel.

## Интеграция с 1С УТ

- COM-подключение к 1С подтверждено через `C:\Users\dpd\Documents\Codex\1C_Diagnostics\test_1c_connect.py`.
- Рабочий `.env` с учетными данными хранится вне репозитория: `C:\Users\dpd\Documents\Codex\1C_Diagnostics\.env`; пароль нельзя выводить, копировать в проект или писать в логи.
- Основной сервер из профиля `UT_DEV`: `pz-sql1.pzmc.org:1541`; если FQDN не разрешается, использовать fallback `pz-sql1:1541`.
- Основной регистр фактических остатков: `ТоварыНаСкладах`; измерения `Номенклатура`, `Склад`, `ХарактеристикаНоменклатуры`, `СерияНоменклатуры`, `Качество`, `Проект`; ресурс `Количество`.
- Контрольные регистры для сверки остатков: `ПартииТоваровНаСкладах`, `ТоварыОрганизаций`.
- Быстрый путь ответа на точечный вопрос об остатке: `.\onec_integration\lookup_1c_stock.cmd "<код или часть наименования>" "<секция или склад>"`, затем читать `onec_integration/reports/quick_stock_lookup.json`.
- Целевой быстрый режим для пользовательских запросов: прогретый read-only helper-сервер `onec_integration/start_stock_lookup_server.cmd` + `query_stock_server.cmd`, основной регистр `ТоварыНаСкладах` без контрольной сверки; контрольные регистры включать только флагом `-Control`. Для списков до 30 строк передавать значения через `-Item "код1" "код2"` в один запрос. Холодный COM-старт остается fallback и может занимать около 50 секунд.
- Прямая синхронизация остатков встроена в WPF через `OneCStockSyncService` и скрипт `onec_integration/tools/sync_stock_sections.py`; она читает только основной регистр `ТоварыНаСкладах`, закрепленные группы складов "НЗП/ЦМО" и "Склад", и не выполняет запись в 1С. План внедрения зафиксирован в `onec_integration/docs/STOCK_SYNC_IMPLEMENTATION_PLAN.md`.

## Важные ограничения и риски

- Прямое подключение к базе IPS по-прежнему не используется. Для PDF-чертежей применяется внешний read-only `IPS Bridge 3.3.1` по MCP; параметры берутся из `config.toml`/`ips_bridge_config.toml`, переменных окружения или внешнего контура `Интеграция с сервисами`, без сохранения секретов в репозитории.
- Живая синхронизация остатков встроена в WPF-приложение через внешний Python/COM-контур. Если 1С или внешний `.env` недоступны, приложение не очищает предыдущий снимок и продолжает работать с последними сохраненными остатками; Excel-импорт остается резервным каналом.
- Единицы измерения пока пересчитываются только при полном совпадении. Нет правил пересчета `шт <-> пог. м <-> кг` через геометрию/массу.
- Индивидуальные сроки поставки и изготовления пока не разделены по этапам, но в библиотеке связи детали с заготовкой хранится общий срок заготовки `BlankLeadTimeDays`; базово 30 дней.
- В `MainViewModel.cs` еще могут оставаться старые поврежденные статусные строки в редко используемых сообщениях; основные списки единиц, видов заготовок, таблицы и подсказки заготовок очищаются при отображении.
- `MainViewModel.cs` очень крупный и совмещает много экранов. При дальнейших крупных изменениях стоит аккуратно выделять ViewModel по файлам.
- Для десятков тысяч деталей критичны SQL-фильтрация, индексы, постраничность и отказ от лишнего `ToListAsync` до фильтров.
- Excel-файлы предприятия могут быть нестандартными; нельзя упрощать импортеры только под один идеальный формат.
- НЗП сейчас определяется эвристикой: строка остатка 1С с кодом, равным IPS после нормализации цифрового кода до 11 знаков, и единицей `шт`; если IPS встречается в нескольких строках потребности, НЗП расходуется сверху вниз по видимому порядку строк, а детализация потребности показывает остаток до и после каждой строки.
- Редактор размера НСИ принимает как ввод через `D40`, `40`, `40x100`, `40x100x1030`, так и отображаемый формат таблицы `D... W... H... T... S... L...`.
- На текущем этапе заготовки сопоставляются по УТ/1С-коду, детали - по IPS.
- Операционная память проекта восстановлена в `RECOVERY_2026-07-13_17.md`. Команда `git` в текущем PowerShell-окружении недоступна, а `.git` в проекте пустой, поэтому исторические выводы за 2026-07-13 - 2026-07-17 основаны на исходных файлах, текущих исходниках, тестах, `VERSION.md`, `publish/versions` и временных логах сборки.

- После завершения обновления нужно открыть ПО "Заказ заготовок ЦМО" для пользовательской проверки.

## Термины

- IPS - код изготавливаемой детали.
- УТ/1С-код - код номенклатурной позиции заготовки.
- Дата потребности - дата, к которой деталь/заготовка нужна производству.
- Дата потребности заготовки - дата, когда заготовка должна быть обеспечена. Равна дате потребности детали минус срок заготовки из библиотеки, базово 30 дней.
- НСИ - справочник/номенклатура заготовок из 1С.
- НЗП - изделия/детали уже в производстве, которые уменьшают потребность в новых заготовках.
- Каноническая заготовка - нормализованная заготовка, объединяющая разные алиасы/названия 1С.
- Алиас заготовки - конкретная позиция 1С с УТ-кодом и исходным названием.
- Карта расхода - связь детали IPS с заготовкой и нормой расхода.

## Направление развития

- Развивать read-only интеграцию с IPS через `IPS Bridge 3.3.1`: сейчас во вкладке МСК реализовано автоматическое открытие PDF-чертежа при наведении; следующий шаг - показывать список найденных файлов/статус bridge в UI и кэшировать метаданные чертежей.
- Доработать прямую синхронизацию остатков 1С при необходимости: добавить настройки секций/расписания, журнал диагностики синхронизации и ручной выбор снимка для расчета.
- Добавить в библиотеку данных вкладку/раздел "Расчетный срок изготовления" и заменить временные 30 дней на срок по заготовке, группе заготовок или поставщику.
- Позже учесть нормативные сроки поставки, минимальные партии, кратность закупки, остаток после закупки и страховой запас.
- Добавить надежные правила пересчета единиц измерения, если это необходимо бизнесу.
- Улучшить производительность UI и импорта на больших справочниках.
- Разделить крупные ViewModel и стабилизировать кодировку русских строк.
- Расширить диагностику импорта: какие строки пропущены и почему.
- Формализовать статусы качества данных: нет детали, нет заготовки, несколько связей, несовместимые единицы, вне И-012, сомнительная нормализация.
