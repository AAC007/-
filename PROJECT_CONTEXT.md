# PROJECT_CONTEXT.md

## Продуктовая цель

"Заказ заготовок для ЦМО" - настольное приложение для автоматического формирования закупочной потребности по материалам и заготовкам. Оно должно отвечать на практический вопрос снабжения и производства: какую деталь нужно изготовить, какая заготовка для нее нужна, в каком количестве и к какому сроку ее нужно купить, чтобы закрыть текущую производственную потребность с учетом уже имеющихся остатков и НЗП.

Проект рассчитан на развитие: справочник деталей и заготовок должен накапливаться, уточняться вручную, переживать повторные импорты и масштабироваться до десятков тысяч деталей.

## Основной поток данных

1. Пользователь импортирует НСИ/номенклатуру заготовок из 1С.
2. Пользователь импортирует или редактирует библиотеку соответствий: деталь IPS -> заготовка/УТ-код/норма расхода.
3. Пользователь импортирует производственную потребность из ПП.
4. Пользователь импортирует остатки склада из 1С через Excel; подготовлен путь замены на прямую синхронизацию 1С без Excel.
5. Приложение рассчитывает потребность в заготовках:
   - находит деталь по IPS;
   - применяет активную связь с заготовкой;
   - умножает количество деталей на норму расхода;
   - учитывает процент потерь;
   - вычитает НЗП по IPS без учета ведущих нулей в кодах 1С; в пользовательской потребности НЗП отображается как "В производстве";
   - вычитает складской остаток по УТ-кодам/алиасам заготовки;
   - формирует количество к закупке;
   - показывает срок потребности по детали/заготовке;
   - считает дату потребности заготовки как `дата потребности детали - срок заготовки из библиотеки`; базовое значение срока - 30 дней.
6. Пользователь экспортирует Excel-отчет, включая лист "Заявка" для снабжения. Заявка должна содержать список деталей и заготовок со сроками потребности.

## Текущий стек

- .NET 8 / C# / WPF.
- MVVM через `CommunityToolkit.Mvvm`.
- SQLite + EF Core.
- Excel: EPPlus, DocumentFormat.OpenXml fallback-reader.
- Логирование: Serilog.
- Тесты: xUnit + FluentAssertions.

Подробности: `docs/IPS_VIEWER_INTEGRATION_NOTES.md`.

- Для оперативных запросов остатков закреплена команда `onec_integration\lookup_1c_stock.cmd`; она читает `ТоварыНаСкладах` и сверяет результат с `ПартииТоваровНаСкладах` и `ТоварыОрганизаций`.
- Импорт производственной библиотеки соответствий деталей и заготовок.
- Ручное создание, редактирование и удаление/архивирование связей детали с заготовкой; в библиотеке можно добавить строку кнопкой `+`, выбрать заготовку через подсказку по формату `наименование | код`, сохранить выбор по введенному тексту, задать срок заготовки в днях, очистить редактор и удалить одну или несколько выделенных строк. Библиотека показывает также детали без активной заготовки, имеет фильтр "Связь" (`все`, `без заготовки`, `с заготовкой`) и выводит инфостроку с количеством показанных деталей и количеством деталей без заготовки по текущим фильтрам. Карточку детали без заготовки можно редактировать и сохранять без выбора заготовки. При ячеечном выделении редактор библиотеки заполняется по выбранной ячейке/строке, а удаление выделенного собирает строки из выделенных ячеек. При сохранении новой основной заготовки для IPS старые активные связи этого IPS архивируются, чтобы в расчете не оставались разные материалы для одной детали.
- Фильтры и поиск в библиотеке и НСИ; в НСИ можно вручную добавить заготовку кнопкой `+`, очистить редактор, редактировать и удалить строку через контекстное меню; поле "Марка материала" в редакторе НСИ имеет выпадающие подсказки по имеющимся материалам; в фильтре единиц библиотеки используются только расходные единицы `шт` и `пог. м`; среди видов заготовок есть "Поковка".
- В таблице "Библиотеки" используется ячеечное выделение `Cell`; клик по ячейке заполняет редактор, но визуально не выделяет всю строку. `DataGrid.SelectedItem` не привязан к ViewModel, чтобы WPF не пытался выбирать всю строку в режиме `Cell`; команды контекстного меню библиотеки устойчивы к служебным WPF-параметрам, которые появляются при наведении, всплывающих списках и перерисовке таблицы.
- В НСИ отображается инфострока с количеством показанных строк.
- Просмотр применяемости заготовки через панель НСИ; при ячеечном выделении клик по строке/ячейке обновляет применяемость, сопоставление учитывает идентификатор, код УТ, алиасы, наименование, размер и материал.
- В НСИ можно удалить или перенести в архив несколько выделенных строк; остаток на ЦМО отображается как `0`, если по позиции нет количества в последнем снимке остатков.
- Импорт потребности из ПП с обновлением повторно импортированного файла без дублей; повторно импортированная партия поднимается в последние, чтобы вкладка "Потребность" показывала именно загруженный файл. Новые IPS из потребности автоматически создаются как детали без заготовки, в том числе при обновлении существующей партии; библиотека дополнительно сверяет строки потребности и создает отсутствующие карточки деталей по IPS. В библиотеку из потребности добавляются только строки деталей: операции, сборки, узлы, комплекты и монтажные строки не создают карточки деталей; если наименование начинается с обозначения, оно разделяется на `Обозначение` и `Наименование`.
- Вкладка "Подбор заготовок" расположена после НСИ, подбирает позиции НСИ по виду, материалу и размерам детали, оставляет только заготовки, которые больше или равны детали по сопоставимым размерам, и сортирует результат от меньшего припуска к большему. В этой же вкладке можно выбрать или набрать IPS детали без активной заготовки из того же набора, который отображается в библиотеке, указать норму расхода в `шт` или `пог. м` и добавить выбранную заготовку в библиотеку.
- Во вкладке "Потребность" можно вручную добавить строку потребности кнопкой `+`, удалить выделенные строки с возможностью отмены, сохранить ручные строки, ограничить показ по дням, видеть количество уникальных IPS, суммарное количество деталей, колонку "В производстве" по остаткам 1С и боковую панель детализации по выбранной строке IPS; панель можно скрыть и отобразить. В заголовке детализации по IPS показывается общее количество деталей в потребности. Колонка "В производстве" показывает фактический остаток НЗП перед строкой с учетом списания строк выше.
- Импорт остатков 1С.
- Расчет материалов с учетом склада и НЗП; заявка показывает только дефицит к закупке после вычета складского остатка, строки с нулевым количеством к заказу в окне расчета не отображаются. Если для IPS нет активной заготовки, в колонке "Номенклатура" отображается "Новая номенклатура".

Повторный импорт отредактированного общего файла `Библиотека.xlsx` обновляет карточку детали, норму расхода и срок заготовки.

- Вкладка "Настройки" позволяет менять шрифт, размер шрифта, положение верхних кнопок, иконку окна и путь к пользовательскому изображению.

## Важные ограничения и риски

- Для будущей интеграции с IPS Viewer найдена схема чтения объектов/состава/PDF, но не подтверждена строка подключения к базе IPS. Нельзя встраивать живые запросы в приложение до согласования read-only доступа с ИТ или владельцем IPS.
- Живая синхронизация остатков еще не встроена в WPF-приложение; до отдельной команды пользователя приложение продолжает работать через импорт Excel и локальные снимки SQLite.
- Единицы измерения пока пересчитываются только при полном совпадении. Нет правил пересчета `шт <-> пог. м <-> кг` через геометрию/массу.
- Индивидуальные сроки поставки и изготовления пока не разделены по этапам, но в библиотеке связи детали с заготовкой хранится общий срок заготовки `BlankLeadTimeDays`; базово 30 дней.
- В `MainViewModel.cs` еще могут оставаться старые поврежденные статусные строки в редко используемых сообщениях; основные списки единиц, видов заготовок, таблицы и подсказки заготовок очищаются при отображении.
- `MainViewModel.cs` очень крупный и совмещает много экранов. При дальнейших крупных изменениях стоит аккуратно выделять ViewModel по файлам.
- Для десятков тысяч деталей критичны SQL-фильтрация, индексы, постраничность и отказ от лишнего `ToListAsync` до фильтров.
- Excel-файлы предприятия могут быть нестандартными; нельзя упрощать импортеры только под один идеальный формат.
- НЗП сейчас определяется эвристикой: строка остатка 1С с кодом, равным IPS после удаления ведущих нулей, и единицей `шт`; если IPS встречается в нескольких строках потребности, НЗП расходуется сверху вниз по видимому порядку строк, а детализация потребности показывает остаток до и после каждой строки.
- Редактор размера НСИ принимает как ввод через `D40`, `40`, `40x100`, `40x100x1030`, так и отображаемый формат таблицы `D... W... H... T... S... L...`.
- На текущем этапе заготовки сопоставляются по УТ/1С-коду, детали - по IPS.
- Операционная память проекта восстановлена в `RECOVERY_2026-07-13_17.md`. Команда `git` в текущем PowerShell-окружении недоступна, а `.git` в проекте пустой, поэтому исторические выводы за 2026-07-13 - 2026-07-17 основаны на исходных файлах, текущих исходниках, тестах, `VERSION.md`, `publish/versions` и временных логах сборки.

## Термины

- IPS - код изготавливаемой детали.
- УТ/1С-код - код номенклатурной позиции заготовки.
- Дата потребности - дата, к которой деталь/заготовка нужна производству.
- Дата потребности заготовки - дата, когда заготовка должна быть обеспечена. Равна дате потребности детали минус срок заготовки из библиотеки, базово 30 дней.
- НСИ - справочник/номенклатура заготовок из 1С.
- НЗП - изделия/детали уже в производстве, которые уменьшают потребность в новых заготовках.
- Каноническая заготовка - нормализованная заготовка, объединяющая разные алиасы/названия 1С.
- Алиас заготовки - конкретная позиция 1С с УТ-кодом и исходным названием.
- Карта расхода - связь детали IPS с заготовкой и нормой расхода.
