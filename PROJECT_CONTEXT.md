# PROJECT_CONTEXT.md

## Продуктовая цель

"Планирование ЦМО" - настольное приложение для автоматического формирования закупочной потребности по материалам и заготовкам. Оно должно отвечать на практический вопрос снабжения и производства: какую деталь нужно изготовить, какая заготовка для нее нужна, в каком количестве и к какому сроку ее нужно купить, чтобы закрыть текущую производственную потребность с учетом уже имеющихся остатков и НЗП.

Проект рассчитан на развитие: справочник деталей и заготовок должен накапливаться, уточняться вручную, переживать повторные импорты и масштабироваться до десятков тысяч деталей.

## Основной поток данных

1. Пользователь импортирует НСИ/номенклатуру заготовок из 1С.
2. Пользователь импортирует или редактирует библиотеку соответствий: деталь IPS -> заготовка/УТ-код/норма расхода.
3. Пользователь импортирует производственную потребность из ПП.
4. Приложение синхронизирует остатки склада из 1С напрямую; Excel-импорт остатков оставлен как резервный канал.
5. Приложение рассчитывает потребность в заготовках:
   - находит деталь по IPS;
   - применяет активную связь с заготовкой;
   - умножает количество деталей на норму расхода;
   - учитывает процент потерь;
   - вычитает НЗП по IPS через 11-значный цифровой ключ 1С: например, IPS `1802132` сопоставляется с кодом 1С `00001802132`; в пользовательской потребности НЗП отображается как "В производстве";
   - вычитает складской остаток и остаток заготовок в НЗП/ЦМО по УТ-кодам/алиасам заготовки;
   - формирует количество к закупке;
   - показывает срок потребности по детали/заготовке;
   - считает дату потребности заготовки как `дата потребности детали - срок заготовки из библиотеки`; базовое значение срока - 30 дней.
6. Пользователь экспортирует Excel-отчет, включая лист "Заявка" для снабжения. Заявка должна содержать список деталей и заготовок со сроками потребности.

## Текущий стек

- .NET 8 / C# / WPF.
- MVVM через `CommunityToolkit.Mvvm`.
- SQLite + EF Core.
- Excel: EPPlus, DocumentFormat.OpenXml fallback-reader.
- Логирование: Serilog.
- Тесты: xUnit + FluentAssertions.

  - `UnitConversionService` пока разрешает только совпадающие единицы.

  - `ExcelImportService` импортирует 1С-заготовки, потребность, остатки и производственную библиотеку.

  - `ReportExportService` экспортирует расчет и библиотеку в Excel.
  - `DatabaseBackupService` отвечает за резервные копии.

- `src/BlankDemandPlanner.UI`
  - WPF-интерфейс с пользовательским названием ПО "Планирование ЦМО" и разделами: "Главная", "Потребность", "Расчет материалов", "Библиотека", "НСИ", "Подбор заготовок", "Планирование", "Отчет", "План", "История", "Настройки".
  - `MainViewModel.cs` содержит основные ViewModel: dashboard, demand, library, normalization/НСИ, stock, calculation.
  - После открытия главного окна выполняется стартовая загрузка основных вкладок, чтобы Библиотека, Потребность и главные счетчики сразу отражали актуальную рабочую базу, включая восстановление деталей из последней потребности.
  - Основная пользовательская база приложения хранится в `Данные для работы\BlankDemandPlanner.db`, чтобы ручные правки библиотеки и НСИ сохранялись между обновлениями. При первом запуске после перехода база копируется из `%LOCALAPPDATA%\BlankDemandPlanner\BlankDemandPlanner.db`, если новая база еще не создана. Логи и резервные копии остаются в `%LOCALAPPDATA%\BlankDemandPlanner`.

## Текущие возможности

- Во вкладке "Библиотека" у детали хранится условие поставки заготовки: `ТО` и/или `Лазерная резка`. Атрибут находится в карточке детали, отображается отдельной колонкой рядом с материалом, сохраняется в SQLite и выгружается в Excel-экспорт библиотеки.
- Контекстное меню строки "Библиотеки" содержит команду `Карточка объекта`: окно содержит вкладки `Информация по детали`, `Маршрут обработки и трудоемкость`, `СТО и расход` и встроенный PDF-viewer на базе того же поиска чертежей, что используется в приложении. Во вкладке информации можно редактировать основные данные детали, активную заготовку/НСИ, норму, единицу, срок, услуги и условия поставки; сохранение синхронизирует карточку с Библиотекой и активной связью НСИ. Маршрут хранится в `ProductionRouteOperations` по IPS с колонками `№ операции`, `Наименование`, `Рабочий центр`, `Т маш`, `Тнал`, `Твсп`; операции можно добавлять, удалять и переставлять. СТО/оснастка и нормы расхода пока хранятся как JSON в `Settings` по ключу `ObjectCard.Tools.<IPS>`, чтобы данные сохранялись без отдельной миграции. В правой части карточки есть кнопка `Открыть на все окно` для PDF.
- Все верхние рабочие панели команд и фильтров должны использовать плавающую компоновку: при уменьшении окна кнопки импорта, обновления, удаления, сохранения, очистки и другие команды переносятся на доступную строку, а не уходят за правую границу.
- Импорт номенклатуры заготовок из 1С.
- Выполнена разведка установленного `IPS Viewer` для будущей привязки деталей к данным IPS и PDF-чертежам. Закреплены локальный ClickOnce-кэш, основные таблицы `IMS_*`, атрибуты и способ чтения файлов из `IMS_STORAGE.F_FILEBODY`; рабочее подключение к базе IPS пока не найдено. Подробности: `docs/IPS_VIEWER_INTEGRATION_NOTES.md`.
- Подготовлен отдельный проект `onec_integration` для безопасной интеграции с 1С:УТ 10.3: обследование метаданных, COM-клиент, быстрый read-only запрос остатков, синхронизация секций остатков для WPF, шаблоны 1С-модулей, dry-run создания документов, журналирование и предохранители записи.
- Во вкладке "Планирование" есть команда `Запустить в производство`: по выбранной детали МСК приложение рассчитывает доступное количество запуска по последнему складскому остатку материала и активной норме расхода, показывает окно выбора количества и комментарий с № станков, которые закрывают дефицит. При подтверждении создается документ 1С `КомплектацияНоменклатуры`; документ остается непроведенным (`Posted=false`), чтобы не выполнять складское списание без отдельного подтверждения. Для направляющих и других штучных сценариев в окне запуска есть режим `Запуск по 1 шт`: он создает отдельные комплектационные карты по одной детали и автоматически распределяет их по строкам дефицита/№ станков. В этом режиме поле комментария показывает построчный предпросмотр будущих документов, и каждая строка передается как комментарий соответствующей комплектации.
- Правая колонка окна "Информация по детали" во вкладке "Планирование" показывает текущую потребность, количество в производстве и доступное количество запуска. Для SQLite decimal-количества потребности суммируются на стороне приложения после чтения списка значений, без `SUM(decimal)` в SQL.
- Во вкладке "Планирование" есть команда `Услуги на стороне`: пользователь выбирает детали из последнего НЗП 44 секции, выбирает вид услуги (`Хим окс`, `Азотирование`, `Шпоночный паз`, `Термообработка`), задает количество и комментарий. В списке выбора один IPS/код показывается одной строкой с общим количеством НЗП, без повторения под разные проекты; галочка `Только в потребности` сокращает список до позиций, у которых есть строки последней потребности, и автоматически ставит в колонку `Переместить` количество реальной потребности, но не больше доступного НЗП. Галочка `Авто выбор` дополнительно сама отмечает такие строки, при этом ручное изменение галочек и количества остается доступным; при снятии `Авто выбор` автоматически выставленные галочки с позиций потребности снимаются. Для заявки и комментария выбранное количество раскрывается по последней потребности: строки получают `ПС`, `№ станка`, количество и исходную дату потребности; если выбранного количества больше, чем потребность по IPS, остаток попадает отдельной строкой `на склад`. Комментарий 1С группируется по IPS: `Услуги на стороне: <вид> IPS <код> <№ станка> - <кол-во> шт; ...`. При подтверждении создается непроведенный документ 1С `ПеремещениеТоваров` из `44 секция НЗП (незавершенное производство)` в `Детали МУ в обработке на стороне`, но окно остается открытым, чтобы можно было сразу сформировать Excel-заявку. Из этого же окна можно сформировать Excel-бланк заявки на услугу с колонками `№`, `ПС`, `№ станка`, `Код IPS`, `Номенклатура`, `Ед. измерения`, `Кол-во`, `Обоснование`, `Дата потребности`, `Примечание`, `Цена, руб`, `Стоимость, руб`; дата в заявке считается от даты формирования файла: `Азотирование` +10 дней, остальные услуги +7 дней. Если расчетная дата услуги позже исходной даты потребности детали, дата и `СРОЧНО!` в примечании выделяются красным жирным.
- Вкладка "Отчет" расположена сразу после "Планирование" и формирует деловой отчет начальника механического цеха за выбранный период. План выпуска считается по строкам последней потребности, факт выпуска и номенклатура - по read-only отчету 1С о перемещениях из 44 секции на секцию 1 и покраску, выполнение плана и OEE выводятся в KPI. Ремонты, простои, аварии, ФОТ, материалы и запчасти вводятся вручную, чтобы отчет не подставлял недостоверные значения.
- В приложение добавлена локальная авторизация: первый запуск создает администратора через окно первичной настройки, затем вход обязателен. Окно первичной настройки можно растянуть, содержимое прокручивается, а кнопка `Применить` закреплена внизу и остается доступной при крупном масштабе Windows. Обычное окно входа показывает редактируемый выпадающий список активных пользователей и подставляет последний успешно использованный логин из настройки `Auth.LastUserName`; пароль никогда не сохраняется. Пароли хранятся только как bcrypt-хэши с work factor 12, неудачные попытки логируются, после 5 ошибок за 15 минут включается временная блокировка. Админ во вкладке "Настройки" управляет пользователями, генерирует/сбрасывает пароли и назначает права `Чтение`/`Редактирование` по вкладкам; обычный пользователь может сменить собственный пароль. Навигация скрывает вкладки без чтения, а вкладки без редактирования отключают кнопки действий.
- Настройки вида применяются в текущем окне без повторного входа: выбор шрифта и размера сразу меняет главное окно, положение навигации хранится отдельно от положения верхней панели и не сбрасывается при повторном открытии вкладки "Настройки". После сохранения прав выбранный пользователь остается открытым; если изменяется текущая учетная запись, права обновляются в активной сессии.
- В настройках администратор может удалить пользователя из активного списка. Операция выполняется деактивацией `AppUser.IsActive=false`, чтобы сохранить историю входов и аудита; текущего пользователя и последнего активного администратора удалить нельзя.
- Ниже вкладки "Настройки" доступен админский "Режим разработчика": в нем редактируются справочники интерфейса `Ед. измерения`, `Виды услуг`, `Условия поставки заготовки`, `Вид заготовок`. Данные сохраняются в таблицу `Settings` рабочей SQLite-базы по ключу `Developer.ReferenceLists`, загружаются при старте и после сохранения сразу применяются к открытым вкладкам "Библиотека", "НСИ", "Подбор заготовок" и "Расчет материалов". Это справочники отображения/выбора поверх закрепленных доменных enum-значений, поэтому добавление новых учетных единиц или физических видов должно учитывать существующую логику расчетов и 1С.
- Основные кнопки WPF-интерфейса должны оставаться единообразными: овальная форма, одинаковая минимальная высота, спокойные hover/pressed-состояния. Карточки-счетчики на "Главной" ведут себя как кнопки, но подсветка должна совпадать с их скругленным контуром. Пункты главной навигации поддерживают контекстное действие `Открыть в новом окне` для параллельной работы с несколькими вкладками: правый клик не должен переключать активную вкладку главного окна, а открытое второе окно не должно иметь `Owner`, чтобы не сворачиваться вместе с главным окном.
- Контекстное меню пунктов главной навигации создается программно по правому клику. Не возвращать `MenuItem` с обработчиком `Click` внутрь `ListBox.ItemContainerStyle` в XAML: это уже приводило к `XamlParseException` при создании `MainWindow` после успешного входа.
- Во вкладке "Планирование" основной список можно ограничить галочкой `В потребности`; фильтр берет IPS из последней загруженной партии потребности и применяется вместе с текстовым поиском.
- Во вкладке "Библиотека" список можно ограничить галочкой `В потребности` рядом с фильтром связи; фильтр берет IPS из последней загруженной партии потребности и не меняет данные библиотеки.
- Общий ручной поиск строится через `UiSearchText`: ввод без учета регистра, русско-латинские похожие буквы для обозначений, цифровые IPS/коды с ведущими нулями и составные запросы по нескольким полям строки. Например, `00001414993` должен находить `1414993`, а `04.067.02.003 Гайка плоская` должен находить строку, где обозначение и наименование лежат в разных колонках.
- Для НСИ и библиотеки поиск дополнительно понимает пользовательское обозначение диаметра русской буквой `д`: запрос `Круг д60 сталь 20` нормализуется как `Круг D60 сталь 20` и должен находить соответствующие позиции 1С/НСИ.
- Для длинномерных заготовок пользовательский ввод и отображение нормы расхода в библиотеке допускаются в миллиметрах: `62 мм` сохраняется в базе как `0,062 пог. м`. Расчеты материалов, Excel-заявки и комплектации 1С продолжают использовать учетную единицу `пог. м`; остатки длинномерных позиций в НСИ отображаются пользователю в `мм`.
- Текущая рабочая версия объединяет ветку `(3)` с производственным планом (`План`, `Дефицит ЦМО`, `Персонал` из API ПО "Производство") и последнюю линию `Запустить в производство`/комплектации 1С из вкладки "Планирование"; эти направления должны сохраняться вместе при следующих обновлениях.
- Для оперативных запросов остатков закреплена команда `onec_integration\lookup_1c_stock.cmd`; она читает `ТоварыНаСкладах` и сверяет результат с `ПартииТоваровНаСкладах` и `ТоварыОрганизаций`.
- Импорт производственной библиотеки соответствий деталей и заготовок, включая беззаголовочный формат `Данные из МСК.xlsx`. Поддерживаются встреченные порядки колонок: старый 12-колоночный с отдельным размером, нормой, единицей, УТ-кодом и наименованием заготовки; фактический 11-колоночный формат `IPS / обозначение / наименование детали / вид / полное наименование заготовки / материал / УТ-код / ГОСТ материала / ГОСТ сортамента / единица / норма`; компактный 10-колоночный формат `IPS / обозначение / наименование детали / полное наименование заготовки / УТ-код / материал / ГОСТ материала / ГОСТ сортамента / единица / норма`. Если IPS был ранее удален из библиотеки через архивную метку или старый текст `Удалено из библиотеки`, явный импорт МСК/библиотеки очищает след удаления и возвращает строку в рабочий список; при открытии библиотеки также восстанавливаются архивные детали, у которых после импорта уже есть активная связь с заготовкой. Если УТ-код или каноническая заготовка были архивированы в НСИ, импорт МСК возвращает их в активные позиции, чтобы заготовка снова участвовала в списке, поиске и подсказках.
- Ручное создание, редактирование и удаление/архивирование деталей и связей с заготовкой; в библиотеке можно добавить строку кнопкой `+`, выбрать заготовку через подсказку по формату `наименование | код`, сохранить выбор по введенному тексту, задать срок заготовки в днях, очистить редактор и удалить одну или несколько выделенных строк. Библиотека показывает также детали без активной заготовки, имеет фильтр "Связь" (`все`, `без заготовки`, `с заготовкой`) и выводит инфостроку с количеством показанных деталей и количеством деталей без заготовки по текущим фильтрам; незаполненные строки подсвечиваются цветом `#FFCC00`. При удалении карточка детали убирается из видимого списка целиком, ее активные связи деактивируются, а сама карточка получает архивную метку `[MANUAL_LIBRARY_DELETE]`; такая ручная метка не дает автодобавлению из уже загруженной актуальной потребности немедленно вернуть строку обратно. Обычный клик/выделение ячейки в Библиотеке только выбирает строку для копирования, удаления или открытия чертежа и не переносит данные в редактор; редактор заполняется только явной командой контекстного меню `Редактировать`. При сохранении новой основной заготовки для IPS старые активные связи этого IPS архивируются, чтобы в расчете не оставались разные материалы для одной детали.
- Карточка детали в Библиотеке хранит признаки услуг на стороне: `Азотирование`, `ТО`, `Хим. окс`, `Шпон паз`. Во вкладке Библиотека эти признаки отображаются в колонке `Примечание`; редактор показывает их галочками под IPS/обозначением/наименованием.
- Окно `Услуги на стороне` во вкладке `Планирование` не показывает весь НЗП подряд: в список попадают только детали из 44 секции НЗП, у которых в Библиотеке отмечена хотя бы одна услуга. После выбора вида услуги список дополнительно фильтруется по соответствующему признаку детали, а при включении `Только в потребности` - еще и по наличию строки последней потребности. Старый ручной список IPS/кодов для отметки строк убран; выбор выполняется через таблицу, фильтр потребности и галочку `Авто выбор`.
- Во вкладке "Подбор заготовок" можно включить фильтр `С положительным остатком`, чтобы среди подходящих заготовок показывались только позиции с положительным количеством в последнем снимке остатков. Остаток сопоставляется по нормализованным УТ/IPS-кодам.
- Фильтры и поиск в библиотеке и НСИ; в НСИ можно вручную добавить заготовку кнопкой `+`, очистить редактор, редактировать и удалить строку через контекстное меню; верхней кнопки удаления НСИ нет, чтобы удаление выполнялось осознанно через правую кнопку мыши по строке. После удаления НСИ команда `Отменить` восстанавливает удаленную позицию, включая алиас, каноническую заготовку, карты применяемости, ссылки остатков и ссылки старых расчетов. Поиск заготовки в редакторе Библиотеки поддерживает префиксный ввод размеров: `Круг D1` показывает подходящие `D100`, `D115`, `D140` и другие позиции, а не фильтрует как точный диаметр 1 мм. Таблица НСИ после колонки "Склад" показывает одну колонку "Цена": цена читается из локального SQLite-кэша `OneCPriceItems`, валюта объединяется в том же поле, например `100 ₽`; онлайн-обращение в 1С при обычном открытии/редактировании НСИ не выполняется. Поле "Марка материала" в редакторе НСИ имеет выпадающие подсказки по имеющимся материалам, поиск подсказок работает без учета регистра для кириллицы, а выбранное значение закрепляется в редакторе. Поля "ГОСТ материала" и "ГОСТ сортамента" также имеют редактируемые выпадающие подсказки, при этом ручной ввод новых ГОСТов сохранен. В фильтре единиц библиотеки используются только расходные единицы `шт` и `пог. м`; среди видов заготовок есть "Поковка".
- В редакторе НСИ подсказки `Марка материала` строятся только по активным позициям НСИ с активным алиасом, а не по каноническим заготовкам из библиотеки без НСИ. При вводе существующей марки материала ГОСТ материала автоматически подставляется из активной НСИ по самому частому совпадению; при выборе вида заготовки автоматически подставляется ГОСТ сортамента по этому виду, кроме `Покупная`. Ручной ввод ГОСТов остается доступным и не перетирается автоподстановкой.
- В НСИ рабочее добавление позиции выполняется через команду `Добавить из 1С`: пользователь ищет реальную номенклатуру 1С УТ по УТ-коду, IPS/коду 1С или части наименования, выбирает позицию из списка, после чего редактор НСИ получает актуальные код, наименование и единицу измерения из 1С; недоступные в 1С атрибуты НСИ (вид, размер, материал, ГОСТ материала, ГОСТ сортамента) дозаполняются вручную сразу или позже. Пользовательская кнопка Excel-импорта НСИ в интерфейсе убрана, чтобы новые позиции не заводились в обход 1С. При первом открытии вкладки "Нормативно-справочная информация" в текущем сеансе и при ручном нажатии `Обновить данные 1С` активные УТ/IPS-коды НСИ пакетно сверяются с реальной 1С УТ; если в 1С наименование изменено, `SourceName`, нормализованное имя и имя канонической заготовки обновляются в SQLite.
- В таблице "Библиотеки" используется ячеечное выделение `Cell`; клик по ячейке заполняет редактор, но визуально не выделяет всю строку. `DataGrid.SelectedItem` не привязан к ViewModel, чтобы WPF не пытался выбирать всю строку в режиме `Cell`; команды контекстного меню библиотеки устойчивы к служебным WPF-параметрам, которые появляются при наведении, всплывающих списках и перерисовке таблицы.
- В НСИ отображается инфострока с количеством показанных строк.
- На главной панели счетчики показывают актуальные рабочие данные, а не накопленную историю: `Деталей` считается по активным строкам библиотеки без архивных карточек, `Заготовок` - по активным строкам НСИ, `К закупке` - по последнему расчету. Карточка `Позиций 1С` убрана. Карточка `Дубли НСИ` открывает НСИ с включенным фильтром `Только дубли`; тот же фильтр доступен в верхней панели НСИ.
- Версия ПО на главной странице берется из верхней записи `VERSION.md`, а не из вручную зашитого текста. Системный заголовок окна остается без версии: `Планирование ЦМО`. В верхнем левом углу рабочей панели показывается только графический знак `Assets\PZMC_1.png`; рядом с логотипом нельзя добавлять версию ПО, slug версии или текстовое название приложения. Брендовый блок главной страницы использует официальный PNG-логотип `Assets\PZMC_.png`; текстовый блок справа от логотипа имеет увеличенный отступ. Значок окна/exe/ярлыка меню Пуск - `Assets\PZMC_1.ico`, созданный из предоставленного изображения.
- Ручной поиск и выпадающие подсказки в рабочих вкладках нормализуют ввод: кириллица ищется без учета регистра, а для кодов и обозначений учитываются похожие русские/латинские символы. Пример: `01-р014` находит обозначения `01-P014...`, а `напра` и `Напра` одинаково ищут по наименованиям.
- Дубли НСИ определяются строгим физическим ключом заготовки: вид, единица, материал, ГОСТ материала, ГОСТ сортамента и точные размеры. Если размеры не распознаны, сравнение может идти по полному имени заготовки, но совпадение только по материалу не считается дублем. Этот же ключ используется на главной карточке `Дубли НСИ`, в фильтре `Только дубли` и в сервисе поиска дублей. В таблице НСИ при показе дублей строки сортируются группами по ключу, чтобы одинаковые пары стояли рядом.
- Просмотр применяемости заготовки через панель НСИ; при ячеечном выделении клик по строке/ячейке обновляет применяемость. Применяемость показывает только детали с активной связью на выбранную каноническую заготовку, без похожих деталей по названию, размеру или материалу.
- В НСИ больше нет пользовательского архива: позиция либо есть в рабочем списке, либо удалена. Удаление выделенных строк физически удаляет выбранные алиасы/заготовки; если по ним есть активная применяемость в библиотеке деталей, перед удалением показывается предупреждение с подтверждением, а после подтверждения активные связи деталей с удаляемой заготовкой снимаются. Старые неактивные архивные алиасы не восстанавливаются автоматически при открытии НСИ.
- Импорт потребности из ПП с обновлением повторно импортированного файла без дублей; повторно импортированная партия поднимается в последние, чтобы вкладка "Потребность" показывала именно загруженный файл. Новые IPS из потребности автоматически создаются как детали без заготовки, в том числе при обновлении существующей партии; библиотека дополнительно сверяет строки потребности и создает отсутствующие карточки деталей по IPS. Если такая деталь уже была удалена из Библиотеки и скрыта архивной меткой `[ARCHIVED_LIBRARY]`, актуальная потребность возвращает ее в рабочий список без заготовки. В библиотеку из потребности добавляются только строки деталей с цифровым IPS длиной 6-11 символов и разделенным обозначением/наименованием: операции, сборки, узлы, комплекты и монтажные строки не создают карточки деталей; если наименование начинается с обозначения, оно разделяется на `Обозначение` и `Наименование`. Если для нового IPS найдено планирование/МСК и в его атрибутах есть УТ-код, библиотека сверяет код с активным НСИ и сразу прикрепляет найденную заготовку, единицу и норму расхода. Во вкладке "Потребность" можно выделять несколько ячеек/строк мышью при удержании левой кнопки.
- Вкладка "Планирование" использует данные из папки МСК, но в Библиотеку автоматически добавляет только строки с нормальным цифровым IPS: 7 или 11 цифр. Короткие числа вроде `463`, дефисы, текстовые обозначения, `ZAGOTOVKA...`, операции и прочие не-IPS строки не создают карточки деталей; ранее ошибочно созданные автозаписи с `Source = МСК` и невалидным IPS очищаются при загрузке/обновлении планирования.
- Вкладка "Подбор заготовок" расположена после НСИ, подбирает только активные позиции НСИ по виду, материалу и размерам детали, оставляет только заготовки, которые больше или равны детали по сопоставимым размерам, и сортирует результат от меньшего припуска к большему. Тип `Поковка` с диаметром `D...` участвует в D-подборе как круглая заготовка, поэтому деталь `D400` может получить варианты `Поковка D450`, `Поковка D660` и другие большие диаметры из НСИ. Канонические заготовки без активного алиаса НСИ в подбор не попадают. Изменение вида, материала или размеров автоматически обновляет список подходящих заготовок после короткой паузы ввода, без обязательного нажатия кнопки "Подобрать". В этой же вкладке можно выбрать или набрать IPS детали без активной заготовки из того же набора, который отображается в библиотеке; подсказки деталей раскрываются при вводе первых символов, выбранная деталь фиксируется в поле, поиск по материалу учитывает материал, каноническое наименование и алиасы НСИ. Справа расположена панель информации по выбранной детали с встроенным PDF-viewer по тому же алгоритму, что и в "Планировании": стабильный кэш, локальные папки чертежей, затем IPS Bridge. После выбора детали и заготовки можно указать норму расхода в `шт` или `пог. м` и добавить выбранную заготовку в библиотеку.
- Вкладка "МСК" читает Excel-файлы из `X:\19_МЕХ УЧАСТОК\База МСК\СПИСОК МСК`, обновляет локальный реестр `MskRecords`, сводит его с библиотекой по IPS, позволяет искать деталь по IPS/обозначению/наименованию/имени файла и открывает исходный Excel-файл МСК. Детальная панель МСК расположена справа и занимает половину вкладки; информация обновляется при поиске и клике/выборе строки, но больше не меняется от простого наведения мыши, а внутренний скроллинг карточки отключен. Основная таблица МСК и детальная карточка не показывают строку `Файл`; путь остается доступен только команде открытия Excel МСК. - Базовое правило планирования закупки: срок заготовки в библиотеке по умолчанию 30 дней, дата потребности заготовки в расчете равна дате потребности детали минус этот срок.
- Разовое назначение заготовки для строк расчета без подобранной связи или для замены в конкретном заказе: пользователь выбирает строку расчета, ищет заготовку строго по активным строкам НСИ (`BlankAliases`) по крупным атрибутам как в подборе заготовок (`Вид`, `Материал`, `D`, `Ширина`, `Высота`, `Толщина`, `Стенка`, `Длина`) и/или текстом по НСИ, задает норму расхода и добавляет заготовку только в текущий расчет; библиотека и НСИ не изменяются, при новом полном расчете разовое назначение сбрасывается.

Поиск деталей без заготовки строится только по видимым активным карточкам Библиотеки без активной заготовки, не показывает архивные/ручные удаленные позиции и не берет детали напрямую из скрытых `Parts`. Если пользователь выбрал конкретную заготовку в результатах, повторное нажатие `Подобрать` сохраняет выбранную строку, если она осталась в результатах, а не сбрасывает выбор на первую позицию. Если по IPS есть данные МСК, атрибуты заготовки подтягиваются оттуда; если нет, явно показывается, что заготовка не подобрана.
- Расчет игнорирует дублирующие активные связи одной детали с той же заготовкой и единицей измерения.
- Экспорт расчета для Bitrix 24 создает файл `Заявка на закуп заготовок ЦМО от <дата> <номер>.xlsx` с листами "Заявка" и "По группе"; цены берутся из локального кэша 1С, без прямого онлайн-запроса во время экспорта. Лист "Заявка" выгружает только непокрытую складом закупочную потребность без колонки "В производстве" и показывает колонку "Цена" сразу после даты потребности заготовки как стоимость строки: для `шт` это количество к закупке * цена за штуку, для `пог. м` - количество к закупке в метрах * цена за погонный метр. Под каждой группой есть скрытые раскрываемые строки деталей, где цена также считается по количеству строки.

## Интеграция с 1С УТ

- COM-подключение к 1С подтверждено через `C:\Users\dpd\Documents\Codex\1C_Diagnostics\test_1c_connect.py`.
- Рабочий `.env` с учетными данными хранится вне репозитория: `C:\Users\dpd\Documents\Codex\1C_Diagnostics\.env`; пароль нельзя выводить, копировать в проект или писать в логи.
- Основной сервер из профиля `UT_DEV`: `pz-sql1.pzmc.org:1541`; если FQDN не разрешается, использовать fallback `pz-sql1:1541`.
- Основной регистр фактических остатков: `ТоварыНаСкладах`; измерения `Номенклатура`, `Склад`, `ХарактеристикаНоменклатуры`, `СерияНоменклатуры`, `Качество`, `Проект`; ресурс `Количество`.
- Контрольные регистры для сверки остатков: `ПартииТоваровНаСкладах`, `ТоварыОрганизаций`.
- Быстрый путь ответа на точечный вопрос об остатке: `.\onec_integration\lookup_1c_stock.cmd "<код или часть наименования>" "<секция или склад>"`, затем читать `onec_integration/reports/quick_stock_lookup.json`.
- Целевой быстрый режим для пользовательских запросов: прогретый read-only helper-сервер `onec_integration/start_stock_lookup_server.cmd` + `query_stock_server.cmd`, основной регистр `ТоварыНаСкладах` без контрольной сверки; контрольные регистры включать только флагом `-Control`. Для списков до 30 строк передавать значения через `-Item "код1" "код2"` в один запрос. Холодный COM-старт остается fallback и может занимать около 50 секунд.
- OData endpoint `http://pz-sql1/ut_dev/odata/standard.odata/` проверен как отдельный read-only канал: опубликованы `Catalog_Номенклатура`, `Catalog_Склады`, `AccumulationRegister_ТоварыНаСкладах` и функция `Balance`. По замеру `Balance` по уже найденным GUID отвечает за десятки миллисекунд, но полный снимок по всем закрепленным секциям пока может упираться в ограничения OData УТ; поэтому в WPF он используется как первый быстрый путь с лимитом 20 секунд и автоматическим fallback на COM. Детали зафиксированы в `onec_integration/docs/ODATA_STOCK_ANALYSIS.md`.
- Прямая синхронизация остатков встроена в WPF через `OneCStockSyncService`: сначала запускается `onec_integration/tools/sync_stock_sections_odata.py`, затем при сбое `onec_integration/tools/sync_stock_sections.py`. COM-скрипт читает только основной регистр `ТоварыНаСкладах`, закрепленные группы складов "НЗП/ЦМО" и "Склад", не выполняет запись в 1С и делает 2 пакетных запроса вместо отдельных запросов по каждой секции. План внедрения зафиксирован в `onec_integration/docs/STOCK_SYNC_IMPLEMENTATION_PLAN.md`.
- Поиск и актуализация номенклатуры 1С для НСИ встроены через read-only `OneCNomenclatureService`: точечный поиск использует `onec_integration/tools/search_nomenclature.py`, а пакетное обновление фактических наименований по списку кодов использует `onec_integration/tools/resolve_nomenclature_codes.py`. Оба скрипта читают `Справочник.Номенклатура`, ищут по коду 1С, УТ-коду/артикулу и нормализованному 11-значному IPS/коду.
- Источник цен НСИ подключен к 1С УТ через read-only `onec_integration/tools/resolve_nomenclature_prices.py`: скрипт пакетно находит номенклатуру по тем же УТ/IPS/11-значным ключам и читает последние ненулевые цены из `РегистрСведений.ЦеныНоменклатуры.СрезПоследних`, предпочитая тип цены `Стоимость`. Результат сохраняется в SQLite-таблицу `OneCPriceItems`; обновление выполняется при запуске программы и при кнопке `Обновить данные 1С` вместе с обновлением остатков. В UI и Excel цена читается только из локального кэша, например `7483,33 ₽`.
- Запуск в производство из вкладки "Планирование" использует OData-скрипт `onec_integration/tools/create_production_assembly_odata.py`, который создает документ `Document_КомплектацияНоменклатуры` по выбранному IPS и активной заготовке. Реквизиты закреплены по ранее проверенной операции: организация `СТП ПЗМЦ АО`, склад `44 секция НЗП (незавершенное производство)`, ответственный `Аракелян Армен Седракович`, подразделение `Цех механической обработки`. Документ не проводится автоматически. Для расчета доступного количества запуска материал считается по группе "Склад" плюс "НЗП/ЦМО", включая 44 секцию, потому что комплектация выпускается через 44 секцию; закупочный расчет материалов применяет это же правило к остаткам самих заготовок по УТ/алиасам, а НЗП деталей по IPS считает отдельно. Для заготовок в `пог. м` запуск учитывает рез 5 мм между деталями и в максимуме запуска, и в количестве компонента 1С. Комментарий документа формируется коротко: только `Создано ПО Планирование` и пары `№ станка; количество`, поле комментария можно вручную отредактировать перед созданием.
- Для документов `КомплектацияНоменклатуры` закреплены проверенные ключи: ответственный `Аракелян Армен Седракович` = `ce72f423-5baf-11ef-864f-0cc47adb8d79`, подразделение `Цех механической обработки` = `14c61f15-1510-11f0-8660-0cc47adb8d79`. Единицы измерения выпуска и комплектующих нужно брать из `Catalog_Номенклатура.ЕдиницаХраненияОстатков_Key`, затем из `ЕдиницаДляОтчетов_Key`; `БазоваяЕдиницаИзмерения_Key` использовать только как крайний резерв, иначе в форме 1С может появиться `<Объект не найден>`.
- Создание документов 1С `ПеремещениеТоваров` освоено через OData-скрипт `onec_integration/tools/create_goods_transfer_odata.py` и подключено во вкладку "Планирование" через `OneCGoodsTransferService`. Проверенный маршрут создает непроведенный (`Posted=false`) документ с отправителем `44 секция НЗП (незавершенное производство)`, получателем `Детали МУ в обработке на стороне`, организацией `СТП ПЗМЦ АО`, ответственным `Аракелян Армен Седракович`, подразделением `Цех механической обработки` и включенными флагами управленческого, бухгалтерского и налогового учета. Пустой документ допускается только как пробный `--empty-trial`; для реального перемещения обязательно указывать строки `--item "<код>" "<количество>"`, чтобы не выбирать номенклатуру по догадке.
- Для будущего раздела отчетов подготовлен read-only OData-скрипт `onec_integration/tools/build_onec_ut_reports_odata.py`. Он строит два отчета за период: перемещения из `44 секция НЗП (незавершенное производство)` на `1 секция (ПЗМЦ) только для производственных целей` и `Покраска ТМЦ` по строкам `Document_ПеремещениеТоваров.Товары`; списание материалов из 44 секции "из сырья в детали" по `Document_КомплектацияНоменклатуры`, где выпуск детали берется из шапки документа, а списанный материал - из табличной части `Комплектующие`. По умолчанию отчеты берут только проведенные документы (`Posted=true`), непроведенные включаются только флагом диагностики.

## Важные ограничения и риски

- Прямое подключение к базе IPS по-прежнему не используется. Для вкладки "Планирование" пользовательский сценарий открытия PDF работает через быстрый локальный кэш/локальные PDF и read-only `IPS Bridge 3.3.1` только при локальном промахе; запись в IPS не выполняется. Для отображения PDF используется локальный PdfiumViewer; пакет старый и дает предупреждение NU1701 при сборке под .NET 8, но этот же подход найден в ПО "Производство".
- Живая синхронизация остатков встроена в WPF-приложение через внешний read-only OData/COM-контур. Если OData недоступен или не укладывается в короткий лимит, приложение автоматически переходит на COM; если 1С или внешний `.env` недоступны полностью, приложение не очищает предыдущий снимок и продолжает работать с последними сохраненными остатками; Excel-импорт остается резервным каналом.
- Текущая авторизация встроена в WPF и SQLite; для размещения "на сервисе" нужен отдельный backend/API. Серверный режим должен быть только HTTPS, с cookie `Secure`, `HttpOnly`, `SameSite=Strict`, CSRF-защитой при cookie-сессиях, backend-валидацией входных данных, rate limiting на `/login` и `/register`, журналированием неудачных входов и админским endpoint сброса пароля.
- Единицы измерения пока пересчитываются только при полном совпадении. Нет правил пересчета `шт <-> пог. м <-> кг` через геометрию/массу.
- Индивидуальные сроки поставки и изготовления пока не разделены по этапам, но в библиотеке связи детали с заготовкой хранится общий срок заготовки `BlankLeadTimeDays`; базово 30 дней.
- В `MainViewModel.cs` еще могут оставаться старые поврежденные статусные строки в редко используемых сообщениях; основные списки единиц, видов заготовок, таблицы и подсказки заготовок очищаются при отображении.
- `MainViewModel.cs` очень крупный и совмещает много экранов. При дальнейших крупных изменениях стоит аккуратно выделять ViewModel по файлам.
- Для десятков тысяч деталей критичны SQL-фильтрация, индексы, постраничность и отказ от лишнего `ToListAsync` до фильтров.
- Excel-файлы предприятия могут быть нестандартными; нельзя упрощать импортеры только под один идеальный формат.
- НЗП сейчас определяется эвристикой: строка остатка 1С с кодом, равным IPS после нормализации цифрового кода до 11 знаков, и единицей `шт`; если IPS встречается в нескольких строках потребности, НЗП расходуется сверху вниз по видимому порядку строк, а детализация потребности показывает остаток до и после каждой строки.
- Редактор размера НСИ принимает как ввод через `D40`, `40`, `40x100`, `40x100x1030`, так и отображаемый формат таблицы `D... W... H... T... S... L...`.
- На текущем этапе заготовки сопоставляются по УТ/1С-коду, детали - по IPS.
- Операционная память проекта восстановлена в `RECOVERY_2026-07-13_17.md`. Команда `git` в текущем PowerShell-окружении недоступна, а `.git` в проекте пустой, поэтому исторические выводы за 2026-07-13 - 2026-07-17 основаны на исходных файлах, текущих исходниках, тестах, `VERSION.md`, `publish/versions` и временных логах сборки.
- Запись `v2026.07.17.3-ui-library-nsi-fix` есть в `VERSION.md`, но отдельная папка `publish/versions/v2026.07.17.3-ui-library-nsi-fix` не найдена; код этой версии присутствует в текущем рабочем дереве.

- После каждой значимой доработки нужно синхронно обновлять `VERSION.md` и `SESSION_HANDOFF.md`; если меняются бизнес-правила или архитектурный контекст, обновлять также `PROJECT_CONTEXT.md`.
- Если публикуется новая сборка, имя записи в `VERSION.md` и имя папки в `publish/versions` должны совпадать.
- Работу по обновлениям и версиям нужно вести в `C:\Users\dpd\Documents\Заказ заготовок для ЦМО\publish\versions`; каждое опубликованное обновление должно иметь отдельную папку версии.
- После завершения обновления нужно открыть ПО "Планирование ЦМО" для пользовательской проверки.
- При каждом опубликованном обновлении пользовательское название `Планирование ЦМО` должно сохраняться в системном заголовке окна, метаданных сборки и ярлыке меню Пуск; системный заголовок окна должен быть без версии, а верхняя рабочая панель должна сохранять только логотип `PZMC_1.png` без версии и текстовых подписей рядом с ним; ярлык `Планирование ЦМО.lnk` в `%APPDATA%\Microsoft\Windows\Start Menu\Programs` должен указывать на exe актуальной опубликованной версии.

## Термины

- IPS - код изготавливаемой детали.
- УТ/1С-код - код номенклатурной позиции заготовки.
- Дата потребности - дата, к которой деталь/заготовка нужна производству.
- Дата потребности заготовки - дата, когда заготовка должна быть обеспечена. Равна дате потребности детали минус срок заготовки из библиотеки, базово 30 дней.
- НСИ - справочник/номенклатура заготовок из 1С.
- НЗП - изделия/детали уже в производстве, которые уменьшают потребность в новых заготовках.
- Каноническая заготовка - нормализованная заготовка, объединяющая разные алиасы/названия 1С.
- Алиас заготовки - конкретная позиция 1С с УТ-кодом и исходным названием.
- Карта расхода - связь детали IPS с заготовкой и нормой расхода.
